# 김감독 지각 방지 대작전 (Gamdok Runner) 게임 기획

## 1. 개요

김감독이 회사에 지각하지 않도록 돕는 미니 게임. 캐릭터 커스터마이징을 통해 플레이어의 개성을 표현하고, 플랫포머 러너 형식의 게임 플레이를 통해 순발력과 판단력을 요구한다.

## 2. 게임 목표

죽지 않고 목적지까지 도착하는 것을 목표로 한다. 도착 시 최종 점수에 따라 Good, Normal, Bad Ending 중 하나가 결정된다.

- **Good Ending**: 일정 점수 이상 획득
- **Normal Ending**: 일정 점수 미만 획득 (게임 성공)
- **Bad Ending**: 점수가 마이너스이거나, 안 좋은 아이템 획득 또는 구멍에 빠져 게임 오버 시

도중에 발생하는 장애물을 피하고, 좋은 아이템을 획득하여 시간을 단축하거나 점수를 높일 수 있다. 안 좋은 아이템 획득 시 점수가 감점된다.

## 3. 주요 기능

### 3.1. 1단계: 형준이 옷 입히기 (캐릭터 커스터마이징)

- **개념**: 게임 시작 전, 플레이어가 김감독 캐릭터를 커스터마이징할 수 있는 화면을 제공한다.
- **활용 이미지**: `public/full_body.png` (기본 캐릭터 이미지로 활용)
- **커스터마이징 요소**:
    - **헤어스타일**: 다양한 헤어스타일 선택 (이미지 레이어 추가 방식)
    - **상의/하의**: 다양한 상의 및 하의 선택 (이미지 레이어 추가 방식)
    - **색상 팔레트**: 각 의상 및 액세서리의 색상 변경 (CSS 필터 또는 미리 준비된 색상별 이미지)
- **저장**: 커스터마이징된 캐릭터는 게임 플레이에 적용되며, 선택 사항은 로컬 스토리지에 저장되어 다음 플레이 시 로드될 수 있다.

### 3.2. 2단계: 형준이 도착지까지 이동시키기 (플랫포머 러너)

- **개념**: 김감독 캐릭터가 자동으로 앞으로 달려나가며, 플레이어의 조작(클릭/탭)에 따라 점프하거나 장애물을 피하며 회사까지 이동한다.
- **게임 화면 구성**:
    - 배경: 약속장소로 향하는 길
    - 플레이어 캐릭터: 커스터마이징된 김감독
    - 장애물: 발판, 구멍, 지형지물 (벽, 언덕 등), 안 좋은 아이템 (획득 시 게임 오버)
    - 아이템: 좋은 아이템 (예: 커피(속도 증가), 시계(시간 추가), 동전(점수 증가))
    - UI: 남은 시간, 점수, 체력 바 등
- **조작 방식**:
    - **스페이스바**: 점프 (슈퍼마리오와 유사한 플랫포머 조작감을 목표)
- **게임 플레이 루프**:
    1. 캐릭터 자동 전진.
    2. 플레이어는 장애물을 피하거나 아이템을 획득하기 위해 적절한 타이밍에 점프/스킬 사용.
    3. 장애물 충돌 시 체력 감소 또는 속도 저하.
    4. 체력이 모두 소진되거나 시간이 초과되면 게임 오버.
    5. 회사에 도착하면 게임 성공 및 결과 화면 표시 (점수, 남은 시간 등).

## 4. 기술 스택 (예상)

- **프론트엔드**: Next.js, React
- **게임 로직/렌더링**: Canvas API를 우선적으로 활용. 만약 개발 과정에서 성능 또는 복잡도 문제가 발생할 경우, Pixi.js (2D 게임 라이브러리) 도입을 고려. (Next.js의 기존 미니게임들이 Canvas를 활용하는 패턴을 따른다.)
- **상태 관리**: React Context 또는 Recoil/Zustand 등
- **애셋**: `public/full_body.png`를 기본으로 하여, 커스터마이징 요소 및 장애물, 아이템 이미지 추가 생성 필요.

## 5. 기술 스택 관련 제안

Next.js와 Canvas API만으로 직접 2D 게임을 구현하는 것은 가능하나, 스프라이트 관리, 충돌 감지, 애니메이션, 물리 엔진 등 기본적인 게임 엔진 기능을 직접 구현해야 하므로 개발 비용이 높을 수 있습니다.

**Pixi.js**와 같은 2D 렌더링 라이브러리는 WebGL/Canvas 렌더링을 추상화하여 스프라이트 애니메이션, 이미지 로딩, 텍스트 렌더링 등을 쉽게 처리할 수 있게 해줍니다.

**결론**: 초기 개발은 Next.js의 Canvas API를 사용하여 진행하고, 추후 복잡도나 성능 문제가 발생하면 Pixi.js와 같은 전문 2D 라이브러리 도입을 검토하는 것을 권장합니다.

## 6. 스킬 시스템

- **스킬 발동 조건**:
    - 게임 내 특정 아이템 획득 시

- **스킬 예시**:
    - **시간 지연**: 짧은 시간 동안 게임 화면의 시간이 느려진다. (장애물 회피 및 정밀 조작에 용이)
    - **자석**: 일정 시간 동안 화면 내의 모든 좋은 아이템을 자동으로 끌어당긴다.
    - **방어막**: 1회에 한하여 장애물 충돌 피해를 무효화한다.

## 8. Full_body.png 활용 방안 논의

`full_body.png`는 단일 이미지 파일이므로, 커스터마이징을 위해서는 몇 가지 전략을 고려해야 합니다:

1.  **레이어 방식**: `full_body.png`를 기본 레이어로 두고, 그 위에 모자, 안경, 옷 등의 커스터마이징 요소를 투명 배경 PNG 이미지로 겹쳐서 표시합니다. 각 요소는 별도의 이미지 파일로 관리하고, 선택에 따라 동적으로 로드하여 렌더링합니다.
2.  **스프라이트 시트/아틀라스**: `full_body.png` 내에 캐릭터의 여러 부위(머리, 몸통, 다리 등)를 분리하여 두고, 커스터마이징 시 해당 부위만 교체하는 방식입니다. 이 경우 `full_body.png`를 부위별로 잘라내어 사용하는 전처리가 필요할 수 있습니다.
3.  **프로그래밍 방식**: `full_body.png`의 특정 색상 영역을 식별하여 CSS 필터나 Canvas API를 통해 색상을 변경하는 방식입니다. (예: 옷의 색상 변경)

**우선, 레이어 방식이 가장 구현하기 용이하고 유연성이 높을 것으로 예상됩니다.** `full_body.png`를 기반으로 다양한 의상 및 액세서리 이미지 파일을 추가로 제작해야 합니다.
